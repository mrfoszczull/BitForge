# Security Policy

## Supported Versions

Security updates are provided for the latest stable release of BitForge.

| Version | Supported |
| ------- | ---------- |
| Latest release | Yes |
| Older releases | No |

## Reporting a Vulnerability

If you discover a potential security vulnerability in BitForge, please report it responsibly.

**Please do not disclose security vulnerabilities publicly through GitHub Issues.**

Instead, use one of the following methods:

- Report the vulnerability privately through [GitHub Security Advisories](https://github.com/mrfoszczull/BitForge/security/advisories/new).
- If private reporting is unavailable, contact the project maintainer through GitHub.

When reporting a vulnerability, please include:

- A description of the vulnerability.
- Steps to reproduce the issue.
- Potential security impact.
- Affected versions.
- Any suggested fixes, if available.

## Response Process

The project maintainer will:

1. Review the report and attempt to reproduce the issue.
2. Assess its severity and impact.
3. Work on a fix when the vulnerability is confirmed.
4. Coordinate disclosure and publish a security update when appropriate.

Please allow reasonable time for investigation and remediation before publicly disclosing a vulnerability.

## Scope

This policy covers security vulnerabilities in the BitForge project itself, including its source code, build configuration, and officially maintained components.

Reports concerning third-party dependencies should be directed to their respective maintainers unless the vulnerability results from how BitForge uses them.
